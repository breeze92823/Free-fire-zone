# Free Fire Zone

An original third-person ONLINE team shooter on a blocky island (Bloxity platform game). Two teams of real players (blue vs orange, 3 v 3 rounds in a 6-player server room, a full room sends the next player to another room; no bots) fight timed respawn rounds on "Coral Key" with a shrinking safe zone, supply crates, airdrops, frost walls, grenades, operatives with Q abilities, knock-down + revive, and a lobby with shops.

Detailed code documentation lives in `docs/` (start at `docs/README.md`: architecture, boot order, frame loop, phases, "where to change what"; then `gameplay.md`, `ui.md`, `engine.md`, `world.md`, `avatar.md`, `audio.md`, `bloxity.md`). The server and the wire protocol are in the backend's `docs/server.md` and `docs/protocol.md`. Read the page for the area before changing it, and update it when the change makes it wrong.

## Rules
- Currency: **coins**, earned in matches (eliminations, knocks, damage, win/loss, MVP) and granted by the server, buy skins, operatives and Store items. Nothing is ever sold for premium currency (see the root CLAUDE.md). Prices live in `src/config.js` (`WEAPONS`, `GRENADES`, `PASSES` in Gems; `SKINS`, `OPERATIVES`, `STORE` in coins) and the backend's `catalog.ts`.
- **Gems** (`profile.gems`): the game's own currency, NOT Bloxity Gems / premium currency. Earned only by playing: knocks, eliminations and round results (`GEMS` in `config.js` = backend `rules.ts`), claimed missions and rank-up rewards (`MISSIONS`, `RANKS` = backend `progress.ts`), granted by the server (`reward` at the kill: HUD kill popup beside the crosshair + multi-kill banner; the round's share at the results). Shown in the lobby top bar and on the results. Spent in the **Weapons Store**: every weapon (`WEAPONS[id].price`), grenade (`GRENADES`) and the Field Arsenal Pass (`PASSES`) costs Gems; skins, operatives and the Store stay in coins. Allowed only while Gems can never be bought: never sell Gems for real money, Bloxity Gems or ads, and never convert anything purchasable into Gems.
- All tunables are in `src/config.js`; the island's own layout data is in `src/world/layout.js`.
- Never bind P (CrazyGames/Boxity pause). Esc frees the mouse and opens the portal menu.

Three.js (vanilla) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; top-level await, `build.target: 'es2022'`). Everything is procedural (canvas textures, box models, synthesized audio); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka.

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` skips the Bloxity SDK/CDN and connects to `ws://<host>:2567` (or `VITE_SERVER_URL`): run the backend's `npm start` (`ROUND_SECONDS=30` for short rounds). Two local players: a second tab with `?devUser=dev-someone2`. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- Dev hooks (dev server, or any build with `?debug` in the URL): `window.__game` has `G` (game state), `step(n, dt, draw)` (run frames synchronously), `play()` (press PLAY), `net` (the connection), `teleport(x, z, facing)`, `shot(name, width, cam)` (render a frame and save it to `.shots/<name>.jpg` via the dev/preview server's `/__shot` endpoint in `vite.config.js`), `setView`, `useItem`, `combat`, `hud`, `profile`. A hidden browser pane stops `requestAnimationFrame` (and throttles timers), so drive frames with `step` and inspect them with `shot` + reading the JPEG.

## Game flow (`src/main.js`, online)
Boot: SDK -> renderer -> Rapier -> lighting, sea + clouds (`world.js`), island (`src/world/index.js` `buildIsland`), loot crates, player body, nav grid, effects, zone, map picture -> HUD + lobby -> avatar (async) -> once auth settles, `net.connect()` joins a server room (the lobby, shops and save need it). Phases in `G.phase`: `lobby` (menus) -> `queue` (PLAY sent: the waiting panel until 2 players are ready, then the server's 15 s map vote: `MAPS` in `config.js` = a world + a district + a mood each (Coral Key: The Villa / day, Old Farm / sunset, Dockyard / night; Dustline Ridge / desert, the big island, card tagged BIG MAP), card pictures rendered by `mapimage.js renderMapShot` (at boot, or when the world is built), voters' heads on the cards; the safe zone closes in on the voted map's `focus` and the intro flyover starts there; X hides the panel, the PLAY button reads "Map voting..." and reopens it, "Leave the team" leaves the queue) -> `intro` -> `countdown` -> `playing` -> `ending` (slow motion) -> `results` -> `queue` (next round in the same room) or `lobby` (Lobby button = `leave`). `syncFlow()` follows the server's phase every frame; the server's clock drives `G.time`. The lobby has its own scene + bloom composer; the game world is only rendered in a match.

## Online (`src/net.js`, `src/game/online.js`)
- `net.js`: connect with backoff (Bloxity `net.resolveEndpoint` + a new Colyseus Client each time; never a socket to `<id>.host.bloxity.io`), `?roomId=` (Open Rooms / invites) via `bloxity.locateRoom`, `?instantMultiplayer=true` private rooms, party roomKey in the join options + `party.joined`, `updateRoom(relay~roomId, team)`, the game token in the join options. Close code 4100 = this account joined elsewhere (no rejoin). `send(type, msg)`, `onNet(type, fn)`, `me()`.
- `online.js`: remote players are Actors with `remote` + `netId`, built from the roster (`reconcile`), drawn `NET.interpDelay` behind their newest pose (`applyRemote`); the local player's hp / life / armour / stats mirror the server (`applyState`); `sendPose` ~20 Hz with `FLAG` bits. Server events -> the game bus (`damage`, `knock`, `elimination`, `revive`, `spawn`, `shot` tracers + sound, `throw`, `boom`, `wall`, `ult`, `opened`, `matchEnd`), chat bubbles for others (`uid`), friend-join notifications (`trackRoster`).
- Bloxity looks (`src/avatar/look.js` `buildLook`), the same for the local player, other players in a round and the lobby platform: 1) custom character (`equipped.characterId` -> SDK `getCharacterFor` GLB, accessories via `characterAccessoryMatrix` / `rig.anchors`), 2) the character kit (`Legion.SDK.character.dress` with the outfit key; the kit shapes the body from the key's proportions; when the portal has it on), 3) by hand (`avatar/loader.js`: composed skin with shirt / pants / face, body parts, every slot from SDK `getAccessorySlots()` + hat and back, placed at `restInverse(bone) x translate(origin)`, hands / shoes mirrored and kept unstretched). Replicated as ids only (`lookToJson`: the whole `getEquipped()` object, proportions, outfit key) via the `avatar` message; the server relays the Bloxity-verified `outfitKey`. A kit outfit is freed with `disposeLook`. Reliability (`avatar/assets.js` + `look.js`): every download goes through one gate (6 at once, local player first, prewarm last) with a timeout, retries and a per-url promise cache that forgets failures; SDK calls (`getCharacterFor`, `kit.dress`) time out at 12 s; `buildLook` reports `complete` (false = a skin / part / accessory failed) and callers use `streamLook` (first usable build shown at once, retried in the background, swapped when complete; used for the local player, lobby mates and remote actors) instead of calling `buildLook` directly; `prewarmLook` builds the other room members' looks in the lobby so the round starts with warm caches. The lobby platform only redresses the mate whose look changed (`showMates`) and re-dresses everyone after a round (`resetMates`). Local testing with the real SDK and the local server: `VITE_DEV_MODE=false VITE_SERVER_URL=ws://localhost:2567`.
- Spectating (eliminated, until Revive): the camera starts on the killer and looks where they look, the arrows (Left / Right) switch to any other player who is up; the panel (`hud.js`, docs/ui.md 2.7) shows the watched player's card (level, rank badge, weapon, distance), their health, hearts (tap / H: `heart`), reactions (`react`, shown over their head), View profile (`profileOf` -> `playerProfile`), the eye counter (state `watch`), Lobby and Revive. `spectate { t }` tells the server who is watched.
- The shooter reports hits (`combat.fire` -> `hit`, `shot`); melee, frag blasts (`boom` with targets in line of sight), heals, abilities, revives (`reviving` / `revive`), crates (`open`) and falling out (`fell`) all go to the server, which decides the outcome. Respawn: the spectate panel's Revive button (after the portal death screen's countdown, or 5 s without the SDK; 20 s without the SDK respawns anyway) sends `respawn`; the server answers `spawn` and `match.spawnActor` picks a safe spot.

## Files (`src/game/`)
- `state.js` shared context `G` (scene, camera, island, actors, player, match, nav, phase, time) + event bus (`shot`, `damage`, `knock`, `elimination`, `revive`, `spawn`, `loot`, `airdrop`, `explosion`, `matchEnd`, ...).
- `actor.js` one character (the local player or another player, `remote`): health/armour/life (`alive`/`knocked`/`dead`), 4 weapon slots (primary, secondary, knife, fists), items, ability charge, stats, the model (avatar + animator + baked held/back weapons + name tag) and hitboxes (capsule + head sphere, laid flat when knocked).
- `characters.js` blocky stand-in characters (worn until a Bloxity look loads; seeded per session id for other players) with the player.glb proportions + bone names (outfits, faces, hair, hats, team armband), portraits for the HUD. `weaponModels.js` procedural weapons (every `WEAPONS` model, with named moving parts) + skins, grenades, projectiles, medkit. `icons.js` renders them to PNG icons + the SVG UI icons.
- Arsenal (`WEAPONS`, each with `cat`, `desc`, Gem `price`): pistols hornet, talon, gnat (full auto), mantis (machine pistol), drifter (revolver); rifles striker (starter), ridgeback, kestrel (armour-piercing), falcon (fast bullpup), sentinel (3-round burst), tempest (LMG), marksman (DMR), sparrow (light DMR), whisper (silenced), hawk (sniper), osprey (bolt-action), ranger (lever-action); shotguns thunder, breaker (2-shot), cyclone (auto), rattler (semi-auto box mag), sawback (sawn-off, secondary slot); SMGs viper (starter), wasp, bulldog (drum), swarm (50-round top mag); heavy quill (crossbow), thumper (grenade launcher), rhino (rocket launcher); melee slot (`loadout.melee`) knife (starter), machete, crowbar (smashes frost walls), pan (worn on the back, blocks shots from behind); specials ronin (blade, +15% run speed) and mender (medic pistol: shots heal teammates); grenades frag, pulse, breach, leech (sticky), molotov (fire pool), smoke, flash (stun) (`GRENADES`, the loadout's T throwable). Guns have moving parts (slides, bolts, levers, cylinders, magazines: `Actor.animateParts`), their own synthesized shot / action / reload sounds and casings. Details: docs/gameplay.md sections 2, 7.1, 7.2.
- Vehicles (`vehicles.js`, `vehicleModels.js`, `vehicles.css`, `driveTest.js`; docs/gameplay.md section 19): the Jeep (4 seats, 4WD) and the Dune Buggy (2 seats, RWD) on Rapier's raycast vehicle controller (`VEHICLES` / `DRIVE` in `config.js`). E (or the HUD prompt) gets in / out; seated, the player's capsule follows the seat (`player.js setRide`, after each physics tick via `physics.js onAfterTick`), the actor sits (animator 'sit' layer) and the camera chases (`camera.js opts.drive`); W/S/A/D or the stick drive, Space / touch BRAKE is the handbrake; flipped vehicles right themselves; engine sound `audio/engine.js`. Offline: the lobby's **TEST DRIVE** (`main.js enterDrive`, `G.test` + `G.drive`) on Dustline Ridge at West Camp's vehicle bay with a 4-step card. Online (`vehicleNet.js`, backend `vehicles.ts`): Dustline Ridge rounds park a Jeep and a Buggy in each camp; `enter` / `exit` ask the server, which owns the seats (`veh` / `seat`); the driver's client simulates the vehicle and sends `vpose` (others draw it kinematic, interpolated); passengers ride and shoot. Vehicle damage, cover, ramming and the driver's gun are the next milestone.
- `testRange.js/.css` the offline **Weapon Test** range (the store's TEST button): a grass field out at sea with an instructor, dummies and a 3-step guided trial per weapon type (guns, blade, medic, grenades), EXIT and a portal back to the store; `G.test` while it runs (no server; `combat.setLocalHits` resolves hits on the dummies).
- `combat.js` hitscan from the camera (verified from the muzzle), spread, damage falloff, armour, knock/eliminate/revive, melee, explosions. `items.js` frost walls (real colliders that soak bullets), frag grenades, medkit, dash, operative abilities. `loot.js` instanced supply crates (E) + parachute airdrops. `zone.js` shrinking safe zone. `fx.js` pooled tracers, muzzle flashes by style (fixed light pool), GPU particles, shell casings (brass / rifle / shotgun shells), bullet holes, explosions, beams, rings. `projectiles.js` flying rounds (crossbow bolts, 40 mm grenades, rockets; the shooter reports `hit` / `blast`). `areas.js` fire pools, smoke clouds (hide name tags), the stun grenade's white-out.

## Controls
WASD move, mouse look (click grabs the cursor), LMB fire, RMB aim/scope, Shift sprint, Space jump, C/Ctrl crouch, R reload, 1-4 / wheel weapons, G frost wall, T frag, X medkit, F dash, Q ability, E open crate / hold to revive / get in or out of a vehicle, Z emote, M map, Tab scoreboard; driving: W/S gas and brake / reverse, A/D steer, Space handbrake, mouse looks around; while eliminated: Left / Right switch the watched player, H heart, G Revive. Touch (standard mobile-shooter layout): left joystick (push to the rim to sprint) with a second FIRE beside it, drag right side to look, big FIRE bottom-right (drag while holding to aim) with CROUCH / AIM / JUMP on a ring round it and RELOAD + frag / frost wall / medkit / dash on an outer ring, weapon bar over the health bar at the bottom centre (ability diamond at its end), minimap top-right (tap = big map) with the emote button beside it. Portrait widens the camera's FOV (`CAMERA.fitAspect`) so the character does not fill a tall screen.

## Bloxity layout
Boxity draws its menu/chat/emotes/etc. in a toolbar in the top-left corner with the chat feed under it; the game never draws those and keeps HUD out of those rectangles. `bloxity.onReservedAreas` feeds `hud.js` (`--res-bottom`, `--res-top`, `--res-rtop`, `--score-shift`) and `lobby.js` (`--res-right`, `--res-bottom`, compact top bar).

## Bloxity integrations (docs.bloxity.io/#html5; checklist in `BLOXITY_CODE_METADATA.md`)
All SDK calls live in `src/bloxity.js` (never throw without the SDK). Done: init/loading/gameplayStart+End (per match), auth + avatar, settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`, `master_volume`), reserved areas, ad breaks (`main.js frame()` freezes, audio muted via `setBreakMuted`), screen ads (`AD_SCREENS` declares every screen with `show: false`, so `showAdScreen` only reports the screen and hides ads), 4 leaderboards (`LEADERBOARDS` declared here; the scores are reported by the server's `reporters.ts`), the death screen (`hud.setDeath` drives the spectate panel's Revive button; with the SDK the portal's countdown decides, without it Revive works after `NET.respawnFallback` 5 s and `NET.autoRespawn` 20 s respawns an idle player), portal emotes (`animator.writeClip`; other players' clips are fetched when first seen, `online.js loadPortalClip`; an emote lasts `emoteLength`), chat bubbles, multiplayer (`net.js`: `resolveEndpoint`, Open Rooms `?roomId=`, friends `updateRoom`, party play, play with friends) and server-side stats. Not applicable (see the metadata file): Gems (never sold), rewarded ads, music volume. Deploy the backend with `roomSize`, never `seatCap`.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path. Use Pointer Events, never mouse-only events. Everything feeds `inputState` in `src/input.js`. Pointer lock does not exist on touch.
- **Detection**: `matchMedia('(pointer: coarse)')` / touch events, not the user agent. `body.touch-ui` switches the HUD to its touch layout.
- **Layout/UI**: relative units, flex/grid, tap targets >= 44px, `env(safe-area-inset-*)`, readable at 360px, no hover-only interactions, `touch-action: none` on game controls.
- **Resize/orientation**: everything sized to the screen reacts to `resize`.
- **Performance**: respect the graphics presets (DPR, shadow map, bloom, particle counts, view distance, texScale, detail); avoid per-frame allocations. Graphics default to **Auto** (`src/perf.js`): a starting tier from the GPU name / memory / cores, then a frame-rate governor walks `AUTO_GRAPHICS.ladder` during rounds and remembers the rung per GPU (`ffz.auto`). Live: DPR, view distance (fog + camera far; sky and clouds are scaled toward the eye to fit), shadow map size. Shadows on/off, bloom on/off and anisotropy recompile or re-upload everything (measured 8-10 s frozen on an Intel iGPU), so mid-round they only fade and the real switch waits for the round's end (`applyGraphics`). Never change shadows, fog type, the light count or the composer during a round. Shaders and textures are warmed up ahead of time (`src/warmup.js`: lobby at boot, game scene + `game/warmkit.js` samples in the lobby, streamed looks before they are shown); something new that a round creates on the fly with a new kind of material belongs in the warm kit. Load time: texture resolution (`toTexture` downscales), model detail (cylinder sides, vegetation, lamps, small-prop shadows, cheaper sea on Low).
- **Testing**: check UI changes at 375x812, a landscape phone (e.g. 740x360, touch emulation) and desktop.
