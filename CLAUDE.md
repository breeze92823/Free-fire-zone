# Free Fire Zone

An original third-person ONLINE team shooter on a blocky island (Bloxity platform game). Two teams of real players (blue vs orange, up to 9 v 9 per 18-player server room; no bots) fight timed respawn rounds on "Coral Key" with a shrinking safe zone, supply crates, airdrops, frost walls, grenades, operatives with Q abilities, knock-down + revive, and a lobby with shops.

## Docs
Detailed code documentation lives in `docs/` (start at `docs/README.md`: architecture, boot order, frame loop, phases, "where to change what"; then `gameplay.md`, `ui.md`, `engine.md`, `world.md`, `avatar.md`, `audio.md`, `bloxity.md`). The server and the wire protocol are in the backend's `docs/server.md` and `docs/protocol.md`. Read the page for the area before changing it, and update it when the change makes it wrong.

## Rules
- Currency: only **coins**, earned in matches (eliminations, knocks, damage, win/loss, MVP) and granted by the server. Nothing is ever sold for premium currency (see the root CLAUDE.md). Prices live in `src/config.js` (`WEAPONS`, `SKINS`, `OPERATIVES`, `STORE`) and the backend's `catalog.ts`.
- All tunables are in `src/config.js`; the island's own layout data is in `src/world/layout.js`.
- Never bind P (CrazyGames/Boxity pause). Esc frees the mouse and opens the portal menu.

Three.js (vanilla) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; top-level await, `build.target: 'es2022'`). Everything is procedural (canvas textures, box models, synthesized audio); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka.

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` skips the Bloxity SDK/CDN and connects to `ws://<host>:2567` (or `VITE_SERVER_URL`): run the backend's `npm start` (`ROUND_SECONDS=30` for short rounds). Two local players: a second tab with `?devUser=dev-someone2`. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- Dev hooks (dev server, or any build with `?debug` in the URL): `window.__game` has `G` (game state), `step(n, dt, draw)` (run frames synchronously), `play()` (press PLAY), `net` (the connection), `teleport(x, z, facing)`, `shot(name, width, cam)` (render a frame and save it to `.shots/<name>.jpg` via the dev/preview server's `/__shot` endpoint in `vite.config.js`), `setView`, `useItem`, `combat`, `hud`, `profile`. A hidden browser pane stops `requestAnimationFrame` (and throttles timers), so drive frames with `step` and inspect them with `shot` + reading the JPEG.

## Game flow (`src/main.js`, online)
Boot: SDK -> renderer -> Rapier -> lighting, sea + clouds (`world.js`), island (`src/world/index.js` `buildIsland`), loot crates, player body, nav grid, effects, zone, map picture -> HUD + lobby -> avatar (async) -> once auth settles, `net.connect()` joins a server room (the lobby, shops and save need it). Phases in `G.phase`: `lobby` (menus) -> `queue` (PLAY sent: the waiting panel until 2 players are ready, then the server's 15 s map vote: `MAPS` in `config.js` = a district + a mood each (The Villa / day, Old Farm / sunset, Dockyard / night), card pictures rendered at boot by `mapimage.js renderMapShot`, voters' heads on the cards; the safe zone closes in on the voted map's `focus` and the intro flyover starts there; X hides the panel, the PLAY button reads "Map voting..." and reopens it, "Leave the team" leaves the queue) -> `intro` -> `countdown` -> `playing` -> `ending` (slow motion) -> `results` -> `queue` (next round in the same room) or `lobby` (Lobby button = `leave`). `syncFlow()` follows the server's phase every frame; the server's clock drives `G.time`. The lobby has its own scene + bloom composer; the game world is only rendered in a match.

## Online (`src/net.js`, `src/game/online.js`)
- `net.js`: connect with backoff (Bloxity `net.resolveEndpoint` + a new Colyseus Client each time; never a socket to `<id>.host.bloxity.io`), `?roomId=` (Open Rooms / invites) via `bloxity.locateRoom`, `?instantMultiplayer=true` private rooms, party roomKey in the join options + `party.joined`, `updateRoom(relay~roomId, team)`, the game token in the join options. Close code 4100 = this account joined elsewhere (no rejoin). `send(type, msg)`, `onNet(type, fn)`, `me()`.
- `online.js`: remote players are Actors with `remote` + `netId`, built from the roster (`reconcile`), drawn `NET.interpDelay` behind their newest pose (`applyRemote`); the local player's hp / life / armour / stats mirror the server (`applyState`); `sendPose` ~20 Hz with `FLAG` bits. Server events -> the game bus (`damage`, `knock`, `elimination`, `revive`, `spawn`, `shot` tracers + sound, `throw`, `boom`, `wall`, `ult`, `opened`, `matchEnd`), chat bubbles for others (`uid`), friend-join notifications (`trackRoster`).
- Bloxity looks (`src/avatar/look.js` `buildLook`), the same for the local player, other players in a round and the lobby platform: 1) custom character (`equipped.characterId` -> SDK `getCharacterFor` GLB, accessories via `characterAccessoryMatrix` / `rig.anchors`), 2) the character kit (`Legion.SDK.character.dress` with the outfit key, `proportions: 'game'`; when the portal has it on), 3) by hand (`avatar/loader.js`: composed skin with shirt / pants / face, body parts, every slot from SDK `getAccessorySlots()` + hat and back, placed at `restInverse(bone) x translate(origin)`, hands / shoes mirrored and kept unstretched). Replicated as ids only (`lookToJson`: the whole `getEquipped()` object, proportions, outfit key) via the `avatar` message; the server relays the Bloxity-verified `outfitKey`. A kit outfit is freed with `disposeLook`. Reliability (`avatar/assets.js` + `look.js`): every download goes through one gate (6 at once, local player first, prewarm last) with a timeout, retries and a per-url promise cache that forgets failures; SDK calls (`getCharacterFor`, `kit.dress`) time out at 12 s; `buildLook` reports `complete` (false = a skin / part / accessory failed) and callers use `streamLook` (first usable build shown at once, retried in the background, swapped when complete; used for the local player, lobby mates and remote actors) instead of calling `buildLook` directly; `prewarmLook` builds the other room members' looks in the lobby so the round starts with warm caches. The lobby platform only redresses the mate whose look changed (`showMates`) and re-dresses everyone after a round (`resetMates`). Local testing with the real SDK and the local server: `VITE_DEV_MODE=false VITE_SERVER_URL=ws://localhost:2567`.
- The shooter reports hits (`combat.fire` -> `hit`, `shot`); melee, frag blasts (`boom` with targets in line of sight), heals, abilities, revives (`reviving` / `revive`), crates (`open`) and falling out (`fell`) all go to the server, which decides the outcome. Respawn: the portal death screen's button (or a 5 s timer without the SDK) sends `respawn`; the server answers `spawn` and `match.spawnActor` picks a safe spot.

## Files (`src/game/`)
- `state.js` shared context `G` (scene, camera, island, actors, player, match, nav, phase, time) + event bus (`shot`, `damage`, `knock`, `elimination`, `revive`, `spawn`, `loot`, `airdrop`, `explosion`, `matchEnd`, ...).
- `actor.js` one character (the local player or another player, `remote`): health/armour/life (`alive`/`knocked`/`dead`), 4 weapon slots (primary, secondary, knife, fists), items, ability charge, stats, the model (avatar + animator + baked held/back weapons + name tag) and hitboxes (capsule + head sphere, laid flat when knocked).
- `characters.js` blocky stand-in characters (worn until a Bloxity look loads; seeded per session id for other players) with the player.glb proportions + bone names (outfits, faces, hair, hats, team armband), portraits for the HUD. `weaponModels.js` procedural guns (AR, SMG, pistol, shotgun, LMG, DMR, sniper, knife) + skins, grenades, medkit. `icons.js` renders them to PNG icons + the SVG UI icons.
- `combat.js` hitscan from the camera (verified from the muzzle), spread, damage falloff, armour, knock/eliminate/revive, melee, explosions. `items.js` frost walls (real colliders that soak bullets), frag grenades, medkit, dash, operative abilities. `loot.js` instanced supply crates (E) + parachute airdrops. `zone.js` shrinking safe zone. `fx.js` pooled tracers, muzzle flashes (fixed light pool), GPU particles, shell casings, bullet holes, explosions, beams, rings.
- `navgrid.js` walkability rasterised from the physics world (spawn points via `randomWalkable`; A* + string pulling remain from the removed bots).
- `match.js` the local round: the player's actor (team + loadout from the server), zone (seeded by the round's `zoneSeed`, same planner as the server), spawn points, MVP badges, local timers. Scores, airdrops (`state.drops` -> `loot.syncDrops`) and rewards come from the server. `controller.js` the player's input -> actions. `results.js` VICTORY/DEFEAT lineup + summary.
- `hud.js/.css` in-match HUD (score, zone timer, squad, minimap + big map (M), kill feed, weapon panel, health/armour, items, ability diamond, crosshair, damage numbers/directions, prompts, knocked/spectate/revive, scope, scoreboard (Tab)). `mapimage.js` renders the island top-down once for the maps.
- `lobby.js/.css` lobby UI (Weapons Store + skins, Store, Characters, Inventory, Settings, mode select, map vote, loading screen); `lobbyScene.js` the 3D hangar with the squad. `save.js` the profile mirror (coins, rank points, owned items, loadout, upgrades, stats): the server sends it (`profile`), purchases / equips are sent as `buy` / `equip` and applied optimistically; a refused one resyncs.
- Root modules kept from the base: `player.js` (kinematic capsule + KCC; the shooter sets `moveSpeed`, `frozen`, `canJump`, `push`, `impulse`), `camera.js` (over-the-shoulder cam with aim zoom, scope, recoil, shake, spectate/orbit/look modes), `input.js` (mouse/keyboard incl. fire/aim/wheel), `touch.js` (joystick, look pad, two FIRE buttons, aim/jump/crouch/reload), `physics.js`, `lighting.js` (moods day/sunset/night via `setMoods`), `postfx.js`, `propkit.js`, `textures.js`, `bake.js`, `avatar/` (animator now has aim/recoil/reload/melee/throw/crouch/knocked/dead/emote layers), `audio/` (synthesized SFX in `sfx.js`, ambience in `index.js`).
- `src/world/` the island (terrain, roads, eight districts: The Villa (0,0), Maple Row (84,0), Fountain Plaza (41,-76), Relay Station (-10,-92), Dockyard (-98,-14), Sunset Beach (0,112), Old Farm (-66,34), Lookout (-62,-72)); `buildIsland(scene, { lighting, preset, maxLamps })` returns `{ radius, bounds, groundHeight, lootSpots, spawnAreas, landmarks, colliders, update, dispose, root, timings }`. Static colliders are merged into ~80 trimeshes on a 32 m grid (much faster for Rapier's character controller than thousands of cuboids); the nav grid and raycasts work on them unchanged. Dev harness: `world-test.html` (`src/world/devview.js`: free-fly camera, 1-8 districts, 0 top-down, `__wv.walkTest`, `__wv.probe`).

## Controls
WASD move, mouse look (click grabs the cursor), LMB fire, RMB aim/scope, Shift sprint, Space jump, C/Ctrl crouch, R reload, 1-4 / wheel weapons, G frost wall, T frag, X medkit, F dash, Q ability, E open crate / hold to revive, Z emote, M map, Tab scoreboard. Touch: left joystick (push to the rim to sprint), drag right side to look, FIRE (drag while holding to aim), AIM/JUMP/CROUCH/RELOAD buttons, HUD buttons for items, weapons, ability, map.

## Bloxity layout
Boxity draws its menu/chat/emotes/etc. in a toolbar in the top-left corner with the chat feed under it; the game never draws those and keeps HUD out of those rectangles. `bloxity.onReservedAreas` feeds `hud.js` (`--res-bottom`, `--res-top`, `--res-rtop`, `--score-shift`) and `lobby.js` (`--res-right`, `--res-bottom`, compact top bar).

## Bloxity integrations (docs.bloxity.io/#html5; checklist in `BLOXITY_CODE_METADATA.md`)
All SDK calls live in `src/bloxity.js` (never throw without the SDK). Done: init/loading/gameplayStart+End (per match), auth + avatar, settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`, `master_volume`), reserved areas, ad breaks (`main.js frame()` freezes, audio muted via `setBreakMuted`), screen ads (`AD_SCREENS` declares every screen with `show: false`, so `showAdScreen` only reports the screen and hides ads), 4 leaderboards (`LEADERBOARDS` declared here; the scores are reported by the server's `reporters.ts`, the client's `submitMatchScores` has no caller), the death screen (`hud.setDeath` Respawn button; with the SDK the portal's countdown decides, without it the `NET.respawnFallback` 5 s timer respawns), portal emotes (`animator.writeClip`), chat bubbles, multiplayer (`net.js`: `resolveEndpoint`, Open Rooms `?roomId=`, friends `updateRoom`, party play, play with friends) and server-side stats. Not applicable (see the metadata file): Gems (never sold), rewarded ads, music volume. Deploy the backend with `roomSize`, never `seatCap`.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path. Use Pointer Events, never mouse-only events. Everything feeds `inputState` in `src/input.js`. Pointer lock does not exist on touch.
- **Detection**: `matchMedia('(pointer: coarse)')` / touch events, not the user agent. `body.touch-ui` switches the HUD to its touch layout.
- **Layout/UI**: relative units, flex/grid, tap targets >= 44px, `env(safe-area-inset-*)`, readable at 360px, no hover-only interactions, `touch-action: none` on game controls.
- **Resize/orientation**: everything sized to the screen reacts to `resize`.
- **Performance**: respect the graphics presets (DPR, shadow map, bloom, particle counts, view distance, texScale, detail); avoid per-frame allocations. Graphics default to **Auto** (`src/perf.js`): a starting tier from the GPU name / memory / cores, then a frame-rate governor walks `AUTO_GRAPHICS.ladder` during rounds and remembers the rung per GPU (`ffz.auto`). Live: shadows, DPR, bloom, view distance (fog + camera far; sky and clouds are scaled toward the eye to fit), anisotropy. Load time: texture resolution (`toTexture` downscales), model detail (cylinder sides, vegetation, lamps, small-prop shadows, cheaper sea on Low).
- **Testing**: check UI changes at 375x812, a landscape phone (e.g. 740x360, touch emulation) and desktop.
